# DEVteam

**A multi-agent AI platform that turns a one-line prompt into a runnable fullstack application — with a live in-browser preview and a production-ready export.**

DEVteam is not a codegen wrapper around a single model. It is an orchestrated team of 11 specialised agents (intent, planner, architect, UI/UX, coder, integration, reviewer, debugger, tester, optimizer, devops) that collaborate through a typed project-state object, with per-role model selection, retry + circuit-breaker routing across OpenAI and Anthropic, and a deterministic preview + export pipeline.

> One prompt in. A reviewed, tested, containerised, downloadable repository out.

---

## Why DEVteam is different

| Most AI code tools | DEVteam |
|---|---|
| Single model, one shot | 11 specialised agents, each with its own role, model, and validation |
| "Looks right" output | Every agent returns strict JSON, validated before entering state |
| Generic UI | A dedicated UI/UX agent emits a real design system (palette, typography, radii, motion, Tailwind config) *before* the coder writes a line |
| Preview is a screenshot | Live in-browser React preview with framework stubs (Next.js, Redux, routing) and mocked backend — deterministic, no sandbox required |
| README is copy-pasted | README, `.env.example`, `.gitignore`, Dockerfile generated from the actual code — not the planner's claims |
| Opaque cost | Per-request cost tracking, per-provider circuit breaker, configurable monthly budget, cheap-model-by-default where quality allows |
| Rebuilds from scratch on every prompt | Follow-up prompts run a 3-stage update pipeline (planner → coder → reviewer) and preserve untouched files |

## Key features

- **11-stage agent pipeline** with intelligent conditional skipping (e.g. `ui_ux` skips on backend-only projects, `optimizer` skips on simple ones). Every skip is recorded and streamed.
- **Multi-provider LLM router** — OpenAI + Anthropic, per-role model selection, exponential-backoff retry with jitter, circuit breaker per provider, automatic fallback, per-request cost tracking.
- **Design-system-first UI generation** — the UI/UX agent runs *before* the coder so generated interfaces follow a coherent visual language instead of defaulting to stock Tailwind.
- **Live in-browser preview** — React/Next.js projects render instantly via Babel-standalone with stubs for `next/link`, `next/router`, `next/navigation`, `next/image`, `react-redux`, `@reduxjs/toolkit`, `redux`. No sandbox, no iframe messaging, fully deterministic.
- **Trustworthy export** — the export ZIP contains the real source plus a README generated by inspecting the code (detecting Next/FastAPI/Django/Prisma/Drizzle/etc.) and an `.env.example` extracted from real `process.env.X` references. Path traversal is blocked at both codegen and zip time.
- **Iterative refinement** — follow-up prompts on an existing project run a shortened planner → coder → reviewer loop and only rewrite files that changed.
- **Realtime pipeline UI** — WebSocket events (`session.started`, `step.started`, `step.completed`, `step.skipped`, `progress`, `session.completed`, `session.failed`) drive a live visualisation of agent progress.
- **Concurrency-safe** — a second prompt against a running project returns 409 with the in-flight session id.
- **Cost-aware by default** — GPT-4o is reserved for planner, architect, UI/UX, and coder; Claude Sonnet reviews; everything else uses `gpt-4o-mini`. Roughly 60% cheaper than a uniform GPT-4o pipeline.

## How it works

1. **You submit a prompt** ("Build a marketplace for freelance designers with auth, Stripe, and a dashboard").
2. **Intent expander** (new, April 2026) rewrites the vague prompt into a detailed product specification — features (core/standard/stretch), UI expectations (pages, components, empty/loading/error states, a11y, design language), quality standards. The expanded prompt is what every downstream agent sees; the original is used only as a fallback.
3. **Intent analyzer** extracts project type, complexity, features, capabilities (`hasFrontend`, `hasBackend`, `hasAuth`, `hasPayments`, …), and a refined prompt.
4. **Planner** selects the stack and writes goals, milestones, risks.
5. **Architect** produces folder structure, component list, API endpoints, data models, styling approach.
6. **UI/UX agent** emits a concrete design system + Tailwind config + `globals.css` (skipped for backend-only projects).
7. **Coder** writes every source file.
8. **Integration agent** wires frontend ↔ backend: fetch clients, shared types, CORS, env vars.
9. **Reviewer** scores the codebase and flags bugs, security, performance.
10. **Debugger** applies fixes for critical/major issues (skipped when none).
11. **Tester** generates unit and integration tests.
12. **Quality enforcer** (new, April 2026) scores UI / functional / code / consistency quality on a 0–100 rubric. On any dimension below 80 it emits concrete patches and missing components (e.g. empty states) before the optimizer runs.
13. **Optimizer** improves perf, readability, a11y, SEO (skipped on simple projects).
14. **DevOps agent** adds Dockerfile, compose file, CI workflow, deploy scripts, `.env.example`.

While the pipeline runs, you watch every step live. When it completes you can:

- Open the **live preview** in the browser.
- Browse the generated source tree.
- Submit a **follow-up prompt** to iterate — only affected files are rewritten.
- **Export** the entire project as a ready-to-run ZIP.

## Example use cases

- **SaaS MVPs** — auth + dashboard + billing + CRUD in one pass.
- **Internal tools** — admin panels, review queues, moderation consoles against an existing API.
- **Marketplaces** — listings, search, messaging, payments.
- **Landing + dashboard combos** — public site plus authenticated app.
- **API backends** — typed REST services with Prisma/Drizzle/SQLAlchemy and Dockerfile.
- **Prototype-to-production handoff** — generate, preview, iterate, export, hand to engineering.

Not a fit for: novice "learn to code" use cases, pixel-perfect clones of existing products, or teams that need white-glove manual architecture (DEVteam picks the stack unless you override it).

## Setup

### Prerequisites

- Node.js ≥ 20, npm ≥ 10
- An OpenAI **and/or** Anthropic API key (at least one)
- Docker (optional, for containerised deployment)

### Install and run

```bash
git clone <repo-url> devteam
cd devteam
npm install

cp .env.example .env
# Edit .env — set OPENAI_API_KEY and/or ANTHROPIC_API_KEY

npm run build
npm run dev
```

- Dashboard: http://localhost:3000
- Backend API: http://localhost:3001
- Health: http://localhost:3001/health

### Running a project

1. Open http://localhost:3000.
2. Enter a prompt in the prompt panel (e.g. *"Build a Next.js + Postgres job board with auth"*).
3. Watch the 11-stage pipeline run live in the agent panel.
4. When the pipeline completes, open **Preview** for a rendered view, or **Files** to read source.
5. Optionally submit a follow-up prompt to refine ("add dark mode", "switch to shadcn/ui", "use Drizzle instead of Prisma"). Only affected files are rewritten.
6. Click **Export** to download the full ZIP.

### Environment variables

| Variable | Required | Default | Description |
|---|---|---|---|
| `OPENAI_API_KEY` | Yes* | — | OpenAI API key |
| `ANTHROPIC_API_KEY` | Yes* | — | Anthropic API key |
| `PORT` | No | `3001` | Backend port |
| `STORAGE_PATH` | No | `./data` | Project + memory storage |
| `JWT_SECRET` | Prod | dev default | Signing secret |
| `MAX_CONCURRENT_SESSIONS` | No | `5` | Pipeline concurrency cap |
| `MONTHLY_BUDGET_USD` | No | `100` | Spend guardrail |
| `ALLOWED_ORIGINS` | Prod | — | Comma-separated CORS origins |
| `NEXT_PUBLIC_API_BASE` | No | `http://localhost:3001` | Web → API base URL |
| `MODEL_<ROLE>` | No | see architecture | Override model per agent role |

*At least one of OpenAI or Anthropic is required.

## Export — what you actually get

Every export ZIP contains:

- **All source files** produced by the coder, integration, debugger, tester, optimizer, and devops agents.
- **`README.md`** generated by inspecting the code (detects Next.js, React, Vue, Svelte, Angular; FastAPI, Flask, Django, NestJS, Fastify, Express, Koa, Hono, Go, Rust; Prisma, Drizzle, Sequelize, TypeORM, Mongoose, SQLAlchemy) — with the correct install and dev commands for that stack.
- **`.env.example`** extracted from actual `process.env.X` references in the code, not from the planner's claims.
- **`.gitignore`** — language-appropriate.
- **`Dockerfile`, `docker-compose.yml`, CI workflow** when the DevOps agent produces them.

Preview-only files (`/preview-only/`, mocks, in-browser stubs) are stripped from the export. Path safety (`..`, absolute paths) is enforced both when the coder writes a file and again at ZIP time.

## Extending the system

1. Add the role to `AgentRole` in [core/src/types.ts](core/src/types.ts).
2. Add a model mapping in [core/src/config.ts](core/src/config.ts) `modelsByRole`.
3. Create `services/agents/src/agents/<name>-agent.ts` extending `BaseAgent<TInput, TOutput>`.
4. Export from [services/agents/src/index.ts](services/agents/src/index.ts).
5. Wire into [services/orchestration/src/orchestrator.ts](services/orchestration/src/orchestrator.ts) (`buildInitialPipelineState`, `runStep(...)`, merge output into `project.artifacts`).
6. Rebuild and run `node apps/backend/test-system.cjs`.

See [ARCHITECTURE.md §14](ARCHITECTURE.md) for a worked example.
