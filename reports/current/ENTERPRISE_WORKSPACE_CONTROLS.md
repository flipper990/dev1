# Enterprise Workspace Controls

## Outcome

The former read-only settings placeholder is now an interactive enterprise administration center. It establishes the UI and frontend domain architecture for organizations, teams, RBAC, approvals, protected resources, environment policy, and audit evidence without adding authentication providers or pretending policy is enforced by the API.

## Implemented areas

- Organization identity and workspace ownership summary.
- Team creation, team roles, member inventory, invitations, and role assignment.
- Role-based permission matrix for projects, exports, deployments, approvals, membership, policies, and audit access.
- Approval inbox with approve/reject decisions.
- Approval workflow configuration for exports, deployments, and protected project changes.
- Protected projects, protected exports, and protected deployments with workflow assignment.
- Environment policies for production, staging, and development.
- Searchable audit log generated by every control-center state transition.

## Architecture boundary

The controls persist as a versioned browser policy draft through `localStorage`. This makes the full interaction model testable while keeping a clear boundary: existing API authorization still uses owner/admin/member/viewer and does not enforce these drafted policies. Identity providers, normalized organization persistence, server-side permission evaluation, durable approvals, and compliance audit storage remain intentionally out of scope.
